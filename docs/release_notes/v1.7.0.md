# OpenPhase v1.7.0

v1.7 makes the phase envelope roughly twice as fast without changing any
result, adds an optional volume translation for densities, and rewrites the
documentation for new users. The Peng–Robinson model, the validation record
and the golden master are unchanged.

## Engine: faster, byte-identical (P9, owner approval A)

- A validation that already succeeded for the very same immutable input (a
  component row, a row tuple, an interaction mapping, a cubic root with the
  same bits) is not repeated. Failures are never cached, and every call path
  and public check is unchanged.
- **Identity proof.** `tools/engine_fingerprint.py` hashes the complete
  result of 801 cases: all 40 validation states both ways, with and without
  Newton and kij, synthetic binaries and ternaries, flash, stability, and the
  app's envelope, overlay, critical point and map. All 801 are identical
  before and after, and the full test suite passes.
- **Speed.** On the same machine, the first phase envelope of each shipped
  example is about 2.1 to 2.4 times faster
  (`docs/investigations/app_performance.md`). The app's time note now states
  what users wait on the public app and on a laptop.
- **P10** records two further speed-ups that would change recorded results.
  Neither is applied.

## Optional volume translation (P11, owner approval C)

- A new module, `src/pvt_phase_simulator/eos/volume_translation.py`, applies
  constant Péneloux shifts to volumes the engine has already computed. No
  solver calls it, so every result is unchanged (801 of 801 fingerprints
  identical). A constant shift cancels in every fugacity ratio, so K-values,
  phase splits, compositions and saturation pressures are unaffected; the
  tests prove it.
- **App.** A collapsed **Advanced: volume translation (Péneloux)** switch, off
  by default, adds one Overview table of phase molar volumes and densities
  with and without the shift. Exports and saved cases are unchanged.
- **Shifts.** A stated fit anchored at the saturated liquid at T_r = 0.7 of
  the accepted pure-component reference file. On the held-out states the
  average liquid-density error falls by a factor of 2 to 3, while the
  worst near-critical error gets slightly worse (`docs/VOLUME_TRANSLATION.md`).

## Documentation

- A new README, a user guide (`docs/USER_GUIDE.md`), a documentation index

  marked not verified.

## Known limits

- **One data source.** Every validation state comes from May et al. (2015).
- **Dew points.** Methane + propane has a unique dew answer at 1 of 23
  measured states. At most of the others PR has two dew pressures, and the
  app reports none, by design.
- **Volume translation is not validated for mixtures.** The shifts are
  fitted to pure saturated liquids only. Near the critical point a constant
  shift makes the liquid density worse.
- **Butanes are not admitted.** A draft PR holds the data file and a
  one-command final step. It waits for the owner's Yang & Richter (2025)
  Table 5 values and for consumer updates listed in its dry-run note.
- **CO2 and N2** exist only as a plan.
- **The first phase envelope of a case still takes about one to three
  minutes.** Measured from click to plot: 103 s on the public app and 115-162 s
  on a laptop (`docs/investigations/app_performance.md`). Repeating a case is
  answered from the cache at once.
- Regenerating the validation record on a different machine can change the
  last digits of some floats. The committed record is unchanged.
